# List item drafts

Keep repeated content in a list and save its items privately.

For: People with list editing access. Last checked: 2026-11-02.

Open a list and choose an item to edit its fields. Required fields must be
complete before saving. Save draft keeps item changes private; the list's normal
review and publishing controls remain separate.

When following a CMS link or switching lists, Keep editing returns to your
fields. Save draft and leave checks and saves the item drafts before opening
your chosen destination. A failed save keeps the fields here. Discard changes
restores locally saved items and does not change a published list. Opening
New list also checks unfinished item edits first.

This rollout covers list items, List settings fields, new-list setup and CSV
source. Browser history has separate recovery limits. The Lists structure is checked locally; fresh-role acceptance
remains open. No Google hosting or live site was used.

A list item form opened on a page now uses the same CMS leave choices. Keep
editing returns to its fields. Save draft and leave checks required fields and
saves the private item before opening the chosen destination. Cancel in the
item form leaves the page's own edits in place and creates no new item. Leaving
the whole page can ask about both page and item work. If a photo or document
picker is open, finish that choice or cancel it before saving the item.

Lists opens the first available list beside the list rail. Choose a list there;
All lists opens the existing index cards. Below desktop width, the List choice
also stays available. New list is in the page header for accounts allowed to
manage list fields; it opens the same private setup dialog.

Table view separates the configured title, subtitle, status and saved update
information. Cards keeps its existing alternative. These are saved item records,
not a claim that private changes are live. Used on links show the affected pages.
Search, filters, CSV import/export, row ordering, bulk actions, List settings and
normal review/publication remain available. An unavailable list address says so
and offers the index without opening a different item editor.

Administrators open List settings under More list actions. Cancel, close and
Escape check unfinished field changes before leaving. Keep editing returns to
the fields; Discard changes restores the opening field design without a save.
Save draft and leave runs the same validated private command as Save fields.
An invalid field or a newer saved version keeps the dialog open with its reason;
compare the saved design before retrying. Neither choice publishes the list.

After saving fields, the existing workflow can ask you to Save draft for the
items against that field design. Fill any newly required values first. Publish
the field changes before putting the updated items live. Earlier field versions
and the current public list stay retained. No permission or field requirement
is relaxed by the leave choices.

New list starts with a preset and its generated address/key. An untouched
dialog can close without creating anything. If you change its setup, Cancel,
close or Escape offers Keep editing, Discard changes, or Save draft and leave.
Save draft creates one empty private list through the normal creation command
and keeps your current destination; it creates no items and publishes nothing.
Create list still saves the private list and opens it directly.

A missing name or failed/uncertain creation keeps your setup open with its
reason. Check Lists before retrying an uncertain response. Closing a creation
already started cannot cancel the server request; the existing completion
notice reports a late result without navigating away from your current list.

CSV import starts as a dry run. Closing or pressing Escape after changing its
source offers Keep editing, Discard changes and Save draft and leave. This
save keeps the raw source only in this browser, for the signed-in account, site
and list. It does not create list items. It also preserves incomplete CSV work
so you can fix the preview later. Browser storage can be cleared by the browser;
keep the original file if you need another copy.

Reopen Import / Export to recover that source. Check its preview against the
current list fields before using Add to draft. That button stages valid new
items alongside existing items and clears the saved source to avoid repeating
the import on reopening. Save draft then saves the list items privately; normal
review and publication remain separate. Clear saved CSV source removes the
browser copy. Discard changes returns to the last saved source, if one exists.

Closing the CSV step leaves other unfinished item changes alone. Leaving the
whole CMS screen checks both item work and CSV source. If browser storage fails,
Save draft and leave stays open with the source intact; copy it, retry or discard
the changes. No source is inherited by another account or a different list.

Saved page links appear under Used on N pages. Open it
to follow a page; the link list scrolls without pushing records away. The compact
table keeps full names and details on hover. Reorder with the row Actions menu
or drag; the old separate up/down buttons now live in that menu. At 1024, open an
item for its saved update details. Records scroll above the grouped publishing
controls, which never cover a record. Advanced uses the shared disclosure style.

List settings keeps move/remove actions in each field's Actions menu. Its
Required checks, choice inputs and Save fields command keep their existing
meaning. Item drawers use the same compact Field and Button controls as the
other Admin screens; their fixed Cancel/Save row stays within the window.

Apply saved field changes means the list fields were saved earlier and the items
need saving against them. It does not mean you edited an item in this session.
The same Save draft, field publication and item review steps still apply. At 1024
the list choices sit above the shared record table; full long titles remain on hover.
