# Pages and new pages

Find a page, change its menu links, or start a private page draft.

For: Content editors, Site admins and Super admins. Last checked: 2026-11-03.

Main pages and Ways We Help keep the page list short. The eight SAWSO sector
pages are in Ways We Help. Stories stay in Stories; search pages and stories
at the top to find either. A story result opens its Story editor. Choose
Drafts to find ordinary pages that have never been published.

Site admins change In the menu and In the footer here or on the matching
Header & menu/Footer screen. Both screens use the same saved drafts. The
switch does not publish. Open Publish to review the named links that changed.
Drag a page handle to move it before another row, or focus the handle and use
Up/Down. This changes the list order and the menu's page-sibling order. It
keeps dropdown groups and other website links in place. A stale result asks
you to reload rather than overwrite another person's save.

New page has a title (90 characters), an address you can Change, a description
for search (155 characters), and Start from. Addresses use lowercase letters,
numbers and hyphens; an invalid address shows an explanation beside the field. Use a blank page, a shared page
design, or a copy of a page on the same site. The result stays private. Site
admins can turn on its optional menu link (off by default); visitors see it after publication.
They can also choose A link to another website. That adds only a menu draft;
there is no page to edit. The existing menu link name limit is 80 characters.

Cancel and Escape use the shared unfinished-work choices. Save draft and leave
creates the private page before leaving. A required field or failed save keeps
your fields. If creation cannot be confirmed, check Pages before trying again.
Content roles cannot use these controls to change the site menu or footer.
Sites brought in with their original design retain their existing creator.

Development checks pass in Chromium and WebKit, including saved shared drafts,
old-version and foreign-page refusal, normal reviewed publication and all four
creation choices. Chromium uses drag; WebKit uses the handle’s keyboard path.
The final numbered acceptance walk and the wider sidebar/site-switcher design
pass remain open.


The native Pages toolbar keeps search beside the page-group filters. Menu
placement and dates stay readable in compact rows. At tablet width, open the page
by its linked title. Its single row menu keeps Edit, View live and every
management action together at both widths. Keyboard users can focus the move handle and use Up/Down. These
layout changes do not publish work or change the shared menu commands.
