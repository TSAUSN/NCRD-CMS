# Stories

Find stories, adjust tags and save private writing before reviewing publication.

For: Story editors, Content creators and site administrators within their access.
Last checked: 2026-11-04.

## Before you start

- If Stories is not enabled, a Site admin opens **Settings → Stories**, names the
  tag groups and chooses **Turn on Stories**. The new library starts empty and private.
- Site admins manage the catalog through **Manage tags**. See [Story tags](story-tags.md).
- Saving, tagging and previewing create private drafts. Publication is a separate review.
  Content creators submit for review; page-only chapter access does not grant Stories access.

## Steps

1. Open **Stories**. Search titles and descriptions, then combine the status and
   tag filters. **Needs review** and missing-tag filters help find unfinished work.
2. Click a tag to add or remove it. The choice saves as a draft and marks the Story
   **Reviewed**; that mark does not grant publishing rights.
3. Wait for saves to finish. If a queued change fails, choose **Retry** to apply it
   to the latest saved list, or **Discard** to drop the unsaved choices.
4. Choose **Edit story** to change existing words, or **Add story** to start new writing.
5. Enter **Title**, **Summary** and **Story text**. A new or changed Summary has at
   most 155 characters. An unchanged longer imported Summary can stay as it is.
6. Choose **Choose photo** (or **Change photo** for an existing picture) to open
   the picker, then check its description and confirm.
   **Upload** is inside the picker. **Cancel** keeps the previous choice.
7. Open **Adjust focus point** and check **Card**, **Phone** and **Wide**. Choose
   **Use automatic crop** to clear a custom point. A Story photo cannot be decorative.
8. Set the tags, **Countries** and optional **Story date (optional)**. A draft can remain
   untagged or undated while you finish it.
9. Read **Where it will show**. It updates as you type without saving and explains
   the draft's eligible feeds. Choose **Try again** if the check fails.
10. Choose **Save draft** to keep the writing privately. **Preview** saves before
    opening the saved preview; **Done** returns to writing.
11. Choose **Publish**, **Schedule** or **Submit for review**, within your role's
    access. Follow [Publish or schedule a story](story-publishing.md).
12. Use **Back** when leaving. With unsaved work, choose **Keep editing**,
    **Discard changes** or **Save draft and leave**. A failed save keeps the form open.

Opening **Add story** creates no record. Discarding before the first save leaves
no empty Story. If the creation response is lost, **Retry draft save** recovers
the same request instead of adding another Story.

## Preview and feed visibility

1. From the Stories list, choose **Preview** to see saved drafts using the current
   search, status and tag filters. **More stories** opens the next 24 cards.
2. Use **Back to Stories** to return with those filters. Card links open private previews.
3. To remove a Story and its article from public access, select **Hide from feeds**,
   then review and publish that change. Clear it and publish to restore the same address.
4. Open **Overview** for saved/live tag counts, **Shows on** page links and
   **Leaving soon**. These summaries create no content.

Feeds use a 13-month window based on UTC calendar days. Future dates wait for that
day. An older Story can leave feeds while its published article stays available.
A **Live** Story can still have private changes; check the saved review before publishing.
**Include unreviewed stories in feeds** is a Site admin setting and waits for publication.

For page feeds, choose main and secondary tags in the page panel. A Story must
match one tag in each chosen group; an empty group allows any. **Maximum stories**
is 1–200, with SAWSO sector pages limited to six. See [World View](story-world.md),
[Split View](story-split.md) and [Newsroom order](newsroom-order.md) for widget views
and featured positions. World View and Split View use the supported library of
up to 2,000 entries; ordinary page-feed limits stay as selected.

## Check a connected public source

1. As a Site admin on a connected site, choose **Check for new stories**. Opening
   Stories, **Preview** or **Overview** never starts this check.
2. Read the progress, last successful check and new/updated/no-longer-in-feed counts.
3. Choose **Review new stories** to open **Needs review**. Existing CMS words,
   tags, photos, **Reviewed** and **Hide from feeds** choices are preserved.
4. If the response is lost, choose **Retry check**. After a finished failure,
   **Check for new stories** starts a new explicit attempt.
5. Finish any queued or failed tag saves before checking again. Removed source
   Stories stay as private **No longer in feed** changes until reviewed publication.

Other sites show **Public feed not connected** and can write their own Stories.
A source check does not publish new content or replace CMS-authored writing.

## Resolve a writing conflict

1. Open **Review saved story changes** when saving reports a conflict.
2. Read **My changes** and **Saved changes**, then choose which value to keep for
   each conflicting field. Photo, description and focus stay together.
3. Choose **Keep selected changes**, then **Save draft**. Review again if someone
   else saves before you finish. **Cancel** keeps your unsaved words.

## Limits

- A described lead photo is required for a new Story's first save. Date is required
  for publishing or scheduling, not for a private draft.
- **Where it will show** excludes unrelated drafts on established sites; a private
  site's first publication review decides which draft feeds become public.
- **Author (optional)**, where enabled, accepts a byline up to 120 characters.
- Browser close/reload uses the browser's warning. Use the onscreen **Back** choices
  to save privately before leaving; private browser recovery is not a cloud backup.
- Editing or cropping the same photo does not clear its sample marker or rewrite
  the Media library's own description. Publication still runs its normal checks.
