# Prepare a new site

Keep setup choices private until you explicitly create the site.

For: Super admins. Last checked: November 11, 2026 against the live Name step
and current creation/publishing commands. No production site was created during
this documentation check.

## Steps

1. On **Home** or **All sites**, choose **New site** / **Create a site**. Only
   Super admins can create websites; an Admin manages an existing assigned site.
2. **Name:** enter **Site name**, **Short name** (or **Short address**) and
   **One line about the site**. Choose **Resource site** or **Event site**.
   The short name identifies the site; it is not a custom DNS hostname.
3. Complete **Look**, **Pages** and **Header & footer**. Review the planned page
   titles, addresses, shared name and links. The preview follows these choices.
4. On **Review**, inspect the setup and choose **Create site** once. If asked,
   confirm sign-in in the offered new tab, then return to retry the retained
   setup. A hosted creation request requires recent sign-in. An uncertain result
   should be checked in **All sites** before starting another request.
5. The site and pages are private drafts. Open each page and replace example
   text/photos with approved content. Add its team through **People & access**;
   see [Adding a person](../people/adding-a-person.md).
6. Review the first complete site publication in **Publish**, including site
   look, header/footer, menu and required pages. The first-site review asks for
   the complete design. Resolve the checks and publish only the intended work.
7. Inspect the public test address, including a nested page, menu, images and
   Phone layout. A private site-creation receipt does not prove Hosting works.
   If the test address says **Needs attention**, or Domains has no records,
   ask the hosting operator to check the provisioning failure.
8. Connect a custom domain through the separate [domain runbook](../hosting/domains.md)
   after the hosting path works. Exact records, DNS ownership and a valid HTTPS
   certificate are separate checks. Never guess DNS from the site's short name.

To start from the national design instead, open the national template and
choose **Start a site from this**.

## Details


A valid setup is saved automatically only in this browser, for the signed-in
account. The saved notice means those choices can be restored here. An invalid
change stays on screen and is not reported as recoverable; the last valid
browser copy remains intact. Complete the required fields before leaving, or
keep editing. Save choices downloads a valid setup file. A setup file is
separate from a full site content archive.

Cancel setup, CMS navigation, and Import an existing site check current setup
work. Keep editing returns to the wizard. Keep draft and leave preserves a
confirmed browser copy; Save draft and leave validates and saves current
choices there before opening the requested destination. Neither choice creates
a site or reserves its address. Discard changes clears this setup and its
browser copy. Clear saved draft does the same while staying in the wizard.

If browser storage cannot save or clear the setup, the leave choice stays open
with its reason and the fields remain here. Keep editing, retry, or save valid
choices to a file. Wait for a setup-file read or an actual site-creation request
to finish before leaving. A recoverable browser copy can survive a reload;
unsaved changes retain the browser's document-departure warning.

This flow is verified locally. Hosting, public domains, DNS and external
sign-in are separate prerequisites; preparing this setup changes none of them.

For a full content archive, use Import site content as a Super admin. Choosing
a supported archive loads its review; Create private draft copy is the separate
command that creates a site. Cancel a CMS departure with Keep editing, return to
the opening/saved setup with Discard changes, or Save draft and leave. That save
keeps the archive bytes and destination only in this browser for this account.
It creates no site or reserved address. Keep the original archive too; another
browser has no recovery copy. Reopen Import site content to resume.

Archive recovery uses asynchronous browser storage because an archive can be
64 MB. A failed or interrupted save never claims recovery, and a failed clear
keeps the fields. Clear saved import setup removes that browser copy. Restore
requires site-file/layout review again. An uncertain import keeps the same
unchanged request across recovery; check Sites before retrying. Changing the
archive or destination starts a new request. Accepted imports clear the browser
copy when storage permits. Wait for file reads/imports before leaving.
