# Chapter destinations

Choose where Find a chapter sends visitors and keep its contact up to date.

For: Admins and division web teams. Last checked: 2026-11-02.

Open Chapters, choose a chapter name, then Set up in its details panel.
Choose This chapter page, Their division’s page,
Their own website or social page, or Not listed yet. A division page has its
own filter and requires a full HTTPS address and a private contact.

The division option has no local chapter page to edit and no editor invitation.
Save draft keeps the public directory unchanged. Open Publish, review the
address and contact changes, and publish the directory link. A new division
link can join the first complete site release; its required page, Site look,
header/footer and menu checks still apply. Existing local pages are retained
separately if the destination changes; they are not silently deleted or archived.

Cancel, Escape and navigation offer Keep editing, Save draft and leave, or
Discard changes. A failed save keeps your fields. The Not listed option keeps
its current behavior; private contact details are not published in the directory.

January and July messages ask a division-page contact to check that the address
works and its information is current. This demo records messages locally and
sends no email. Address not checked means no website request was made; it must
not be presented as Page found. Real address checking remains unverified under
the local-only rules.

Upgrade note: older app versions cannot read the new division destination.
Before stepping back, keep a compatible app or restore the matching database
backup. Do not remove the migration while chapter versions still use this value.

Each chapter page's hero uses its chapter name from Set up. The shared layout,
logo, photos and other wording stay shared. Renaming a chapter updates that
heading on its page draft; review and publish the page normally before visitors
see it. Imported chapters retain the exact name from the source list.

In Settings → Publishing & approval, choose how new chapters start: division staff
make changes, or chapter editors sign in and send changes for approval. Save
chapter defaults applies immediately; existing chapters keep their own setup.
Division teams remain below the default choices. Each chapter's own Set up
screen owns its assigned division. Stories settings is a separate disclosure.

Settings → Review reminders shows January/July and the two message previews.
The check/reminder switches and Save check settings stay visible to site
administrators. Super admins open the closed Test tools (this computer only)
disclosure for month/year, recording controls and the local outbox. This demo
records messages locally. Five working days uses Monday–Friday in Eastern time;
nothing publishes automatically. The preview itself sends or records nothing.

The native Chapters screen keeps the list beside a read-only details panel.
Choose a chapter name to see its saved setup, private contact, enabled sections
and assigned chapter editors. Today it links to describes the published setup;
Saved destination can differ while a draft is waiting. Set up opens the existing
chapter form. Open chapter page opens its CMS page when one is assigned.
Open saved address opens a linked destination in a new tab; it is still unverified.
Set up and Invite a volunteer stay in the details panel, with one action per
chapter row. At 1024, the table keeps chapter names and page status; the panel
holds the other facts. Long email addresses show their full value on hover.
Access-read errors offer Try again and make no chapter change. Address not
checked remains explicit; opening these details makes no external website request.

After inviting a volunteer through the details panel, the assigned-editor list
reloads from saved access. The background inspector is inactive while Set up or
the invitation dialog is open. The invitation stays in this demo's local outbox.

Super admins open Test tools (this computer only) below the Chapters list for
Local outbox. It starts closed and is absent for other roles. Invitations keep
their existing permissions and record locally; no real email is sent.
