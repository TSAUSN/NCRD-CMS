# Schedule a page

Review an exact saved page and choose when it goes live.

For: Editors, Site admins and Super admins with publishing access. Last checked: 2026-11-04.

## Steps

1. In the page editor, choose **Schedule**. It sits beside **Save draft** and
   **Publish**, saves your current changes and prepares a review. Preparing can
   take up to a minute; wait for the result. Nothing is scheduled yet.
2. In **Publish later**, read the changes and checks.
3. Choose a date and time. Times are in your device's time zone.
4. Choose **Schedule selected changes**. The page goes live at that time.

The review covers only this page. Menu, header, footer, list and other page
drafts stay separate; resolve those in **Publish** first if the page needs them.
A new private site must review its complete site design first: use **Review
first site publication** when asked. It does not publish anything by itself.

## Check, stop or retry a schedule

- Open **Publish** and choose the **Scheduled** tab to see each request and its
  status. It stays private until it is applied.
- Choose **Cancel schedule** to stop a future request.
- If a newer version of the page is already live when the time comes, the older
  schedule is skipped and the reason is shown. Review and schedule the current
  page again.
- If a schedule fails, review the page, then choose **Retry failed schedule**.
  The earlier failure stays in the history.

## Details

In Publish later, read the changes and checks, choose a date and time in your device
time zone, and confirm Schedule selected changes. Sample content and exceptional
findings still need their existing explicit review. Cancel, Escape and CMS links
protect changed time/reason fields with Keep editing, Discard changes or Save
draft and leave. Save keeps only those choices in this browser for your account,
site and exact reviewed changes; it never schedules or publishes. Discard returns
to the opening/saved choices. Clear saved choices removes the browser copy. A
failed save or clear keeps the fields here.

To resume, open the same reviewed draft from Publish History, then Publish later.
Review the exact changes and confirm required approvals again. Another browser
has no copy. A stored time can become past or the review can become stale; normal
scheduling checks still refuse these until corrected. Only Schedule selected
changes queues work. An uncertain command keeps the unchanged request for retry;
check Scheduled publishing first. Successful scheduling clears its browser copy
when storage permits.

Repeated interruptions stop an attempt after its allowed retries and leave a
visible failure. Review the page before using Retry failed schedule; the earlier
failure and its reason remain in history.

If saving or preparation fails, your work stays in the editor. A changed saved page
needs another review. If you make more edits during preparation, save them and
choose Schedule again. After an uncertain connection, check Publish before retrying.
The same unchanged request can reopen its saved review without making a duplicate.

There is no automatic end date or change-back date yet. Later changes to a
scheduled page stop the schedule for another review; they are never silently
added.

A clock time skipped when daylight saving time starts is unavailable; choose
another time. When a clock time repeats in autumn, the form chooses its next
future occurrence and names the date, time and zone abbreviation before you
confirm. Check that note. The stored schedule uses that exact instant. Normal
minimum notice, review and permission rules still apply.

The single-page form on Scheduled publishing uses the same private leave choices.
It saves the chosen page, action, time, reason and exact version selection only in
this browser. Restore never silently switches to a newer draft: Reload version
is an explicit review step. A missing page needs another selection. Clear saved
schedule choices removes recovery and reloads the current page selection.

Retry failed schedule keeps its own browser draft for that failed attempt.
Cancel/Escape affect only retry fields; an unfinished single-page form stays
here. Save draft and leave creates no new attempt. Reopen that same failed row
to resume. The failed version remains pinned, and restored exception text must
pass a fresh displayed-finding review before Schedule new attempt is accepted.
Clear saved retry choices resets that setup, keeping the failed history.
